# Cコード説明要領

「AIが生成したコードを説明させる」という課題は、単なるコードレビューではなく、**自分の理解を確認する訓練**になります。ただし、新人の場合は「何を説明すればよいのか」が分からず、結局AIに「説明文を作らせる」だけになる可能性があります。

そのため、最初に**説明の型（レビュー観点）**を渡すのが効果的です。

例えば以下のような「Cコード説明テンプレート」を提示するとよいと思います。


## 1. このプログラムの目的

最初に「何をするプログラムなのか」を説明する。

例：

> このプログラムは、指定された入力ファイルを読み込み、AES-CTRモードで暗号化処理を行い、期待値ファイルと比較することで暗号処理が正しく動作しているか確認するテストプログラムです。

確認すること：

* 何を入力するか
* 何を処理するか
* 何を出力するか
* 何を確認するプログラムなのか

---

# 2. プログラム全体の流れ

処理の流れを文章または図で説明する。

例：

```
main()
 |
 +-- コマンドライン引数解析
 |
 +-- ファイル読み込み
 |
 +-- AES初期化
 |
 +-- AES暗号化実行
 |
 +-- 結果比較
 |
 +-- 終了処理
```

説明例：

> main関数では、最初に入力ファイル名を取得します。その後、ファイルサイズを確認してメモリを確保し、AES処理を実行します。最後に期待値と比較して結果を表示します。

---

# 3. 主要な変数・構造体の説明

すべての変数を説明する必要はない。

重要なものを説明する。

例：

```c
AES_ctx ctx;
```

説明：

> AES処理に必要なラウンドキーや初期化ベクトルを保持する構造体です。

確認ポイント：

* なぜこの型なのか
* 何を保持しているのか
* どこで生成され、どこで使用されるか

---

# 4. 関数ごとの説明

各関数について以下を説明する。

テンプレート：

| 項目  | 内容           |
| --- | ------------ |
| 関数名 | xxx()        |
| 目的  | 何をする関数か      |
| 入力  | 引数の意味        |
| 出力  | 戻り値や変更されるデータ |
| 注意点 | エラー条件など      |

例：

```c
int load_file(
    const char *filename,
    uint8_t **data,
    size_t *size
);
```

説明：

> load_file関数は指定されたファイルを読み込み、確保したメモリにデータを格納します。成功時は0を返し、失敗時はエラーコードを返します。

---

# 5. なぜこの書き方をしているか

ここが新人教育では重要。

「動く理由」ではなく「設計理由」を説明する。

例：

## mallocではなくVirtualAllocを使用している理由

悪い説明：

> AIがそう書いたから。

良い説明：

> 大きなメモリ領域確保やWindows APIとの連携を考慮してVirtualAllocを使用しています。ただしmallocとの違いとして、ページ単位で管理されるため用途によって使い分けが必要です。

---

# 6. C言語特有の注意点

以下を確認する。

## ポインタ

説明：

* 指しているデータは何か
* NULLになる可能性
* 解放責任はどこにあるか

例：

```c
uint8_t *buffer;
```

確認：

> bufferが指すメモリは誰が確保し、誰が解放するのか？

---

## メモリ管理

説明：

* malloc / free
* VirtualAlloc / VirtualFree
* メモリリークの可能性

---

## 型変換

特に注意：

```c
(void *)func
```

や

```c
GetProcAddress()
```

のようなコード。

説明：

> 関数ポインタへの変換を行っているが、型が一致している保証はどこにあるか確認する。

---

# 7. エラー処理

以下を説明する。

* 失敗時どうなるか
* エラーを検出できるか
* リソース解放されるか

例：

悪い：

> fopenに失敗したらreturnする。

良い：

> fopen失敗時には後続処理を実行しないため安全だが、途中で確保したメモリが存在する場合は解放処理が必要になる。


# 最終成果物の形式例

新人には以下の形式で提出させるとよいです。

```
1. プログラム概要
   - 目的
   - 入出力

2. 処理フロー
   - main処理
   - 各関数

3. 重要なコード説明
   - ポインタ
   - メモリ管理
   - API使用理由

4. 設計上の判断
   - なぜこの方法を選んだか

5. 問題点・改善案
   - 現状の課題
   - 修正案

6. 自分が理解できなかった点
```
